# คู่มือลงคลิปสำหรับ Moji · Rod Mai Club (รูปแบบใหม่ 5 พ.ย. 2569 · ใช้ตั้งแต่คิว 6 พ.ย.)

เจ้าของสั่ง 5 พ.ย.: ลงผ่าน **Buffer** โดยเจ้าของหรือ Moji
- ไม่ใช้ YouTube API หรือ Graph API เพราะคลิปที่อัปผ่าน API ของโปรเจกต์ที่ยังไม่ผ่าน audit จะถูกบังคับเป็น private
- Claude ไม่ลงคลิปและไม่ตั้งเวลา มีหน้าที่เตรียมไฟล์และข้อความเท่านั้น
- ไฟล์คิวทั้งหมดอยู่บน branch `ccr-fb88c4b3-kcqyid` ส่วนไฟล์วิดีโออยู่บน branch และ commit ที่แต่ละ item ระบุไว้

## 1. ตารางประจำวัน: วันละ 1 เรื่อง
| เวลา (ไทย) | ไฟล์ | ลงที่ |
|---|---|---|
| 09:00 | Shorts EP.1 | YouTube Shorts · Facebook Reel · Instagram Reel |
| 09:15 | Shorts EP.2 (จบค้าง ชี้ไปคลิปยาว) | YouTube Shorts · Facebook Reel · Instagram Reel |
| 09:30 | คลิปยาว 16:9 ทั้งเรื่อง | YouTube เท่านั้น (สะสม watch hours) |

- EP.3 ไม่ลงเป็น Shorts แยก เพราะอยู่ในคลิปยาวแล้ว
- **ข้อยกเว้น (วาล์วโมเมนตัม):** ถ้า Shorts ตอนไหนได้วิวใน 24 ชั่วโมงตั้งแต่ 22K ขึ้นไป
  - ให้แจ้งแชทประสานงาน
  - แชทจะตัดช่วงหักมุมจากคลิปยาวเป็น Shorts เพิ่ม 1 คลิป
  - คลิปนี้ลง 08:45 ของวันถัดไป

## 2. ไฟล์ที่ต้องใช้ต่อวัน
- **คิวของวัน:** `video/release/day-YYYY-MM-DD.json`
  - `items` มี Shorts EP.1 และ EP.2
  - `video_long` คือคลิปยาว
  - แต่ละไฟล์ระบุ `branch` + `commit` + `video` (path) + `video_sha256` + ปก
  - `complete: false` แปลว่าวันนั้นยังมีไฟล์ไม่ครบ ดูรายการใน `missing`
- **ข้อความทั้งหมดของวัน:** `upload_sheet` (เช่น `video/release/sheets/jk-upload.md`) มีข้อความพร้อมคัดลอกไปวางใน Buffer
  - ชื่อ YouTube
  - คำอธิบาย และ timestamps ของคลิปยาว
  - แคปชัน Facebook / IG
  - แฮชแท็ก
  - คอมเมนต์ปักหมุด

## 3. ขั้นตอนทุกคืน 22:00 (เตรียมของพรุ่งนี้)
1. เปิด `day-<พรุ่งนี้>.json`
2. ดาวน์โหลดทุกไฟล์ที่ `status: final` ตาม `branch` + `commit` + `video`
   - คำสั่ง: `git show <commit>:<path> > file.mp4`
   - หรือดาวน์โหลดจากหน้า GitHub ของ commit นั้น
3. ตรวจ sha256 (`sha256sum file.mp4`) ให้ตรงกับ `video_sha256` ถ้าไม่ตรง ห้ามลง แล้วแจ้งเจ้าของ
4. ตั้งคิวใน Buffer ตามเวลาในข้อ 1 คัดลอกข้อความจาก upload sheet แล้วแนบปก
5. item ที่ `status` เป็น `in_production` หรือ `missing` ห้ามตั้งคิว
   - ถ้าถึง 22:00 แล้วยังไม่เป็น `final` ให้แจ้งเจ้าของ
   - แชทประสานงานจะสลับวันให้ ถ้าทำได้

## 4. กฎข้อความ (ตรวจก่อนวางทุกครั้ง)
- **ชื่อ YouTube Shorts:**
  - ไม่เกิน 40 ตัวอักษร
  - ขึ้นต้นด้วยฮุก
  - ห้ามใส่แฮชแท็กในชื่อ ไม่ต้องเติม `#shorts`
- **ชื่อคลิปยาว:** ใช้รูปแบบ `<สถานการณ์>… อย่า<คำสั่ง> | <ชื่อเรื่อง> ฉบับเต็ม`
- **แฮชแท็ก:** ไม่เกิน 5 ตัว ใส่ไว้ท้ายคำอธิบายหรือแคปชันเท่านั้น
- **คอมเมนต์ปักหมุดของ Shorts:** แหล่งอ้างอิง + ลิงก์คลิปยาว
  - Shorts ลงก่อนคลิปยาว จึงต้องรอให้คลิปยาวขึ้นหลัง 09:30
  - แล้วแทน `<ลิงก์คลิปยาว>` ด้วยลิงก์จริงก่อนปักหมุด
- **คอมเมนต์ปักหมุดของคลิปยาว:** แหล่งอ้างอิงทั้งเรื่อง

## 5. ไฟล์สถานะ (บังคับ)
`video/release/posted/YYYY-MM-DD.json` เป็นรายการ 1 แถวต่อ 1 ไฟล์ต่อ 1 แพลตฟอร์ม
```json
[{"id":"jk-ep1","platform":"youtube_shorts","status":"posted","scheduled_for":"2026-11-06T09:00+07:00",
  "posted_at":"2026-11-06T09:00+07:00","url":"https://youtube.com/shorts/…","views_24h":null,"error":null}]
```
- `status` มีค่าได้ 3 แบบ: `scheduled` | `posted` | `failed`
- `platform` มีค่าได้ 4 แบบ: `youtube_shorts` | `facebook_reel` | `instagram_reel` | `youtube`
- หลังลงครบ 24 ชั่วโมง ให้กรอก `views_24h` เพื่อใช้ตัดสินวาล์วโมเมนตัม
- อัปเดตทุกครั้งที่สถานะเปลี่ยน แล้ว push ขึ้น `ccr-fb88c4b3-kcqyid`

## 6. ลองใหม่และแจ้งเตือน
- ลงไม่สำเร็จ ให้ลองใหม่ 3 ครั้ง เว้นระยะ 2, 5 และ 10 นาที
- ถ้ายังไม่ได้ ให้เขียน `failed` พร้อมข้อความ error แล้วแจ้งเจ้าของทันที
- ห้ามเงียบ และห้ามข้ามแพลตฟอร์มไปเฉยๆ
- ถ้า Buffer ไม่รับไฟล์ (เช่น ใหญ่เกิน) ห้ามบีบหรือแปลงไฟล์เอง
  - ให้แจ้งแชทประสานงาน แชทจะทำไฟล์ขนาดเล็กลงแล้วใส่ path + sha256 ใหม่ในไฟล์คิวของวันนั้น
  - ตรวจ sha256 ของไฟล์ที่ใช้จริงทุกครั้ง

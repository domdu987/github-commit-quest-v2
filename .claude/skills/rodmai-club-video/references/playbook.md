# วิธีทำงานจริงทีละขั้น (playbook)

ไฟล์นี้คือลำดับงานและการตัดสินใจที่ใช้ทำ ตึกโยก EP.1 และ ทะเลลด EP.1 (สองตอนล่าสุดที่ดีที่สุด) ทำตามลำดับ
แต่ละขั้นบอกว่าต้องได้อะไร ทำอย่างไร และตรวจอย่างไร · กติกาที่ต้องผ่านอยู่ใน SKILL.md หัวข้อ 1 · โค้ดอยู่ใน `engine-v2.md`

## สารบัญ
0. เริ่มแชท
1. เลือกเรื่อง
2. ยืนยันความรู้ + ARC.md
3. โลกของเรื่อง + style frames
4. เขียนบท `lines.json`
5. เสียงพูด + QA + จังหวะ
6. เขียนช็อต `body.part`
7. ตรวจเอง → สตอรี่บอร์ด
8. เสียงประกอบ มิกซ์ เรนเดอร์
9. ตรวจไฟล์ ส่งมอบ เก็บ
10. ทำงานขนาน (fork) และการรอ

## 0. เริ่มแชท

1. อ่าน `SKILL.md` ให้จบ แล้วอ่าน `video/STATUS.md` (งานค้าง ขั้นถัดไป) และ `video/<เรื่อง>/ARC.md` ของเรื่องที่ทำอยู่
2. ตั้ง workspace ใน scratchpad (รันจาก root ของ repo · ถ้ามีตอนที่กำลังเรนเดอร์อยู่ใน `<scratchpad>/mw` ให้ใช้โฟลเดอร์ใหม่ เพราะ setup เขียนทับ `hf/lib`):
   ```bash
   K=.claude/skills/rodmai-club-video/scripts; W=<scratchpad>/mw
   bash $K/setup_workspace.sh $W tide1=video/tide/ep1      # ทำต่อจากงานที่เก็บไว้ (เสียงพากย์มาด้วย ไม่เสียเครดิต)
   bash $K/setup_workspace.sh $W flood1                    # หรือเริ่มตอนใหม่จากแม่แบบล่าสุด
   cd $W/tide1 && python3 ../hf/lib/voice.py lines.json vo && python3 timing.py      # สร้าง wav + schedule จาก mp3 ที่เก็บไว้
   cat helpers.part body.part > shots.part && cat head.part sigcard.part shots.part foot.part > ep.tmpl.html && python3 make.py
   (cd $W/hf/tide1 && (python3 -m http.server 8885 >/dev/null 2>&1 &))   # 1 ตอน 1 พอร์ต
   ```

3. ถ้าผู้ใช้ถามคำถาม ตอบก่อนทำอย่างอื่น (ผู้ใช้เคยต้องพิมพ์ "ตอบผมก่อน")
4. บอกผู้ใช้สั้นๆ ว่ากำลังทำอะไร และจะได้อะไรเมื่อไร

## 4. เขียนบท `lines.json`

ลำดับที่ใช้ (ทะเลลด EP.1 = 38 บรรทัด, 1:58):

| ช่วง | ทำอะไร | ตัวอย่างจริง |
|---|---|---|
| 0–3 วิ | ฮุก (กติกา H1–H6) ประโยคแรกสั้น แล้วคำสั่ง | "ถ้าวันหนึ่ง… คุณเห็นทะเลลดลงไปไกล" → "{อย่าลงไปเก็บ}" |
| 3–10 | ย้อนเวลา + สถานที่ + แผนที่ | "สองชั่วโมงก่อน" · "บ้านแหลมหอย ริมทะเลอันดามัน" |
| 10–30 | เปิดตัวละครด้วยมุกในประโยคแรกของแต่ละคน + วางเบาะแส | จูน "เน็ตที่นี่ห้าขีดเลย!" · ตังค์ "ผมจะจับปลาตัวใหญ่ที่สุด!" · ยาย "ร้านพังได้… รูปนี้พังไม่ได้" |
| 30–50 | ข้อเท็จจริงในโลก + ข่าวลือ + กฎ + คนรุ่นใหม่ปัดตก | "แปดโมงเช้าวันพุธ หอเตือนภัยทดสอบเสียง" · "จำไว้ ทะเลถอย อย่าคอยดู" → "ยายก็คิดมาก…" |
| 50–60 | ตำนาน 2–3 ประโยค (S5) | "ชาวมอแกนเรียกมันว่า ละบูน" / "คลื่นยักษ์เจ็ดชั้น" / "เมื่อคนเฒ่าเห็นน้ำทะเลลดผิดปกติ…" |
| 60–75 | ภัยเริ่ม คนดูรู้ก่อน ตัวละครทำผิดต่อหน้า | "ปลาฟรี! ไม่ต้องเสียตังค์!" · "ทุกคนดูนี่! ไวรัลแน่!" |
| 75–90 | ความรู้ เหตุ → ผล + ตัวเลข | "ท้องคลื่นถึงฝั่งก่อน น้ำเลยลด" · "เร็วพอๆ กับเครื่องบินเจ็ท" · "ไม่ต้องรอเสียงเตือน" |
| 90–100 | คนที่ถูกหาว่าบ้าทำสิ่งที่ถูก + คนเยาะ + วิ่ง | "ทะเลถอย! ขึ้นเขา!" → "ตาจุ่นบ้าอีกแล้ว…" |
| 100–110 | **หักมุม** (S14) | คลื่นแรกแค่ท่วมรอบร้าน → "แค่นี้เอง…" → ทะเลถอยอีกรอบ → "ยายล่ะ… ยายอยู่ไหน?" |
| 110–118 | หลักฐานในภาพ + ประโยคปิด 2 ท่อน + ตัวเลือก + การ์ดท้าย | รองเท้ายายบนบันไดร้าน · "คลื่นลูกแรก…" / "ไม่ใช่ลูกที่ใหญ่ที่สุด" |

วิธีเขียนแต่ละบรรทัด:
- ท่อนละ 2–5 คำ แบ่งท่อนใน `cap` ด้วย ` / ` คำสำคัญใส่ `[ ]` (กล่องเหลือง) คำอันตรายหรือคำหักมุมใส่ `{ }` (กล่องแดง)
- บทตัวละครราว 35–40% ของเวลา เป็นภาษาพูดจริงของคนวัยนั้น ผู้บรรยายพูดกับ "คุณ"
- ความรู้ทุกบรรทัดต้องชี้ไปที่ quote ใน ARC.md ได้ และมีชิปที่มาขึ้นจอ
- อ่านบททั้งตอนออกเสียงหนึ่งรอบ ทุกรอยต่อต้องใส่ "แต่…" หรือ "เพราะงั้น…" ได้ (checklist ใน `video/RETENTION.md` หัวข้อ 5)
- ยาวเกิน 2:00 ให้ตัดบรรทัดที่ภาพเล่าเองได้ก่อน (ทะเลลด: ตัด 3 บรรทัดและ 1 ช็อตจาก 2:17 เหลือ 2:00 แล้วตัดประโยคแรกอีกให้ฮุกถึงใน 3 วิ)

## 5. เสียงพูด + QA + จังหวะ

1. เลือกชุดเสียงใหม่ทุกเรื่อง เสนอผู้ใช้ 2–3 ชุด (ทะเลลด: จูน Zephyr · ตังค์ Laomedeia · ยาย Sulafat · ตาจุ่น Algenib · นักท่องเที่ยว Zubenelgenubi · ผู้บรรยาย Puck)
2. style ตัวละคร 4 ส่วน (อายุ/ที่มา · ลักษณะเสียง · อารมณ์ของบรรทัด · ปิดท้ายมาตรฐาน) ดู `audio-and-delivery.md`
   ตัวอย่างจริง: `หญิงชราอายุหกสิบห้า เจ้าของร้านอาหารทะเลริมหาด เสียงอบอุ่น หนักแน่น ดุแต่ห่วงหลาน งงกับมือถือ ขำๆ ใจดี ชัดทุกคำ ไม่กระซิบ พูดประโยคนี้แค่ครั้งเดียว ไม่พูดซ้ำ`
3. `python3 ../hf/lib/voice.py lines.json vo` แล้ว `WHISPER_DIR=<scratchpad>/whisper python3 ../hf/lib/voice_qa.py lines.json vo --fix 2`
4. บรรทัดที่ยังติด (อ่าน `vo/qa.json`):
   - คำผิดหรือหาย → เปลี่ยนถ้อยคำ (ทะเลลด เปลี่ยน 5 บรรทัด เช่น "ตังค์! วิ่งขึ้นเขาเร็ว!")
   - ยาวผิดปกติ (LONG) → เอาคำว่า "ช้าๆ" ออกจาก style
   - คำสำคัญไม่ชัด → เพิ่ม `"take": 2` อัดใหม่ แล้วเลือกเอง (ทะเลลด: y03 กฎ, n16 สะกด "เจ็ท")
   - ทดสอบบรรทัดเดียว: เขียน json ที่มีบรรทัดเดียวแล้วรัน voice_qa กับไฟล์นั้น
     (ระวัง: `vo/qa.json` จะถูกเขียนทับเหลือบรรทัดเดียว ให้รวมผลกลับเข้ารายงานเดิมก่อน commit)
5. `timing.py`: SHOTS = (key, เสียง, pre, post, ขั้นต่ำ) รวม 1:40–2:00 · ช็อตไม่มีเสียงพูด 2.0–2.4 วิ · ช็อตแรกสั้นพอให้คำสั่งมาถึงใน 3 วิ
6. `python3 $K/hookcheck.py .` ต้องได้ PASS

## 6. เขียนช็อต `body.part`

วิธีคิดมุมกล้องและตัวเลขทั้งหมดอยู่ใน `shot-design.md` (มีตัวอย่างครบ 30 ช็อตของทะเลลด EP.1) ลำดับการเขียน:
1. คอมเมนต์บนสุด: ไวยากรณ์ภาพทั้งตอนในบรรทัดเดียวต่อช่วง (ดูต้นไฟล์ `video/tide/ep1/body.part`)
2. preset แสงและเกรดของเวลาในเรื่อง (`SUN` `SHOPL` `EERIE` · `GMORN` `GEERIE` `GSHOP` `GDAY`)
3. helper ของตอน: `A()` นักแสดง, `TALK()` ปากขยับ, `SRC()` ชิปที่มา, `chip()` `tag()` `timeLeft()` `walkDown()`
4. เขียนช็อตตามลำดับเรื่อง หัวช็อตเป็นคอมเมนต์ `// ---------- N. เกิดอะไรขึ้น ----------`
5. ฉากที่ fork ยังสร้างไม่เสร็จ ใส่ stub ให้ตอน build ได้ แล้วลบเมื่อของจริงมา:
   ```js
   if (!Sets.tideShop) Sets.tideShop = (L, o) => Sets.tideBeach(L, { id: o.id, view: "sea", time: "morning" });
   ["clockBack", "wipe", "cupShake"].forEach((f) => { if (!Tide[f]) Tide[f] = () => {}; });
   ```
6. build และถ่ายภาพนิ่งทุก 5–8 ช็อต อย่ารอเขียนครบทั้งตอน

## 7. ตรวจเอง → สตอรี่บอร์ด

ทำตาม `review.md` ทุกข้อ แล้วส่งสตอรี่บอร์ด (`storyboard.py`) ให้ผู้ใช้อนุมัติ (กติกา D1)
ถ้าผู้ใช้สั่งให้เรนเดอร์เลย ("ทำทะเลลดก่อนให้เรนเดอร์ จะได้ไม่ช้า") ให้เริ่มเรนเดอร์ทันทีแล้วส่งสตอรี่บอร์ดไปพร้อมกัน บอกว่าแก้ได้

## 8. เสียงประกอบ มิกซ์ เรนเดอร์

- **เรนเดอร์ภาพก่อน** เพราะช้าที่สุดและไม่ต้องใช้ mix (Bash `run_in_background: true`, `timeout: 7200000`):
  ```bash
  bash $K/render.sh $W/hf/tide1 $W/tide1 EP1-thale-thoi-ya-khoi-du          # ยังไม่มี mix.wav → เรนเดอร์ raw.mp4 อย่างเดียว
  bash $K/render.sh $W/hf/tide1 $W/tide1 EP1-thale-thoi-ya-khoi-du --mux    # หลัง python3 mix.py → ได้ *-HQ.mp4 และ *-share.mp4
  ```
  ความเร็วราว 200 เฟรม/นาที บนเครื่อง 4 คอร์ (คลิป 2:00 = 7,100 เฟรม ≈ 35–40 นาที) · ดูความคืบหน้า: `tail -c 300 render.log`
  ห้ามรัน `make.py` ของตอนที่กำลังเรนเดอร์
- ระหว่างนั้นเขียน `CUES` ใน `mix.py` (ตัวอย่างครบทั้งตอน: `video/tide/ep1/mix.py`):
  - มีเสียงตั้งแต่เฟรม 0 · sting ตรงคำสั่ง "อย่า…" · เสียงทุกการกระทำที่เห็น · หัวใจเต้นช่วงลุ้น · เงียบสนิทหลังตัดดำ
  - `dip()` ลดดนตรีช่วงหลอน · ห้ามเสียงซ่าหรือ noise bed
- `python3 mix.py` → ต้องได้ราว −14 LUFS, พีก ≤ −1 dB (`ffmpeg -nostats -i mix.wav -af ebur128=peak=true -f null -`)

## 10. ทำงานขนาน (fork) และการรอ

- แยกงานให้ fork เมื่อเป็นไฟล์คนละไฟล์กัน (แผนที่ / การ์ด / ฉาก / ตัวละคร) ทะเลลดใช้ 4 fork:
  A ฉากหาดและคลื่น · B แผนที่ 3 มิติและภาพผ่าครึ่ง · C ตัวละครและการ์ด · D ในร้านยาย อินเสิร์ต และคลื่นแรกบนเขา
- brief ของแต่ละ fork ต้องมี:
  1. ไฟล์ที่แก้ได้ (ก๊อป `hf/lib` → `hf/lib_<ชื่อ>`, โฟลเดอร์ตอนของตัวเอง, พอร์ตของตัวเอง) และห้ามแตะ lib จริง
  2. กติกาภาพชุดเดียวกัน (V10: หน้าสว่าง/ด้านเงา/เงาสัมผัส, เส้นหมึก, พาเลต) และพิกัดที่ช็อตจะใช้ (จุดยืน ขนาด id ที่ต้องมี)
  3. ภาพนิ่งที่ต้องส่ง และให้รายงานว่า "ก๊อปไฟล์ไหนไปทับไฟล์ไหน" + จุดที่ช็อตต้องเปลี่ยน
- ระหว่างรอ fork: เขียนช็อตด้วย stub (ข้อ 6)
- รวมงาน: ตรวจว่าไฟล์ใน `hf/lib` ไม่ถูกแก้ตั้งแต่ fork เริ่ม → ก๊อปทับ → build → ถ่ายภาพนิ่งทุกช็อตใหม่ → เก็บเข้า `video/<เรื่อง>/lib/`
- fork ติด rate limit หรือ worker รีสตาร์ต: ปลุกต่อด้วย SendMessage และเปิด http.server ที่ตายใหม่
- ห้าม `sleep` รอ · ระหว่างรอทำงานอื่น · แจ้งความคืบหน้าเป็นภาษาไทยสั้นๆ
- ก่อนจบทุกเทิร์นที่งานยังค้าง: `scripts/wip_save.sh` → commit + push → อัปเดต `video/STATUS.md`

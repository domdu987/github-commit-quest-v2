# ตอนยาว 16:9 แนวนอนจริง (ไม่ใช่แนวตั้งใส่แผง)

ผู้ใช้ปฏิเสธแบบ "แนวตั้งกลางจอ + แผงปกซ้าย/กดติดตามขวา" ทันที (5 พ.ย.) ต้องเป็นภาพแนวนอนเต็มเฟรม ไม่มีแผง ไม่มีปก/ท้ายคลิปในตัววิดีโอ

## 1. ฝาแฝดแนวนอนของแต่ละตอน (`scripts/mkland.py <ep> <proj>`)
สร้าง `<ep>L/` จาก parts แนวตั้งเดิม (คัดลอก body/helpers/sigcard/foot/schedule/lines/mix.wav) และเขียน `head.part` ใหม่:
- stage 1920×1080 (`data-resolution=landscape`, `STAGE_W/H`, `#root`, grain) · `window.LAND=1`
- **แปลงกล้องอัตโนมัติ** ใน `fr()`: `S = s × LAND_K (0.75)`, จุดจอ `sx×1920/1080`, `sy×1080/1920` → ทุกช็อตคงตำแหน่งสัมพัทธ์เดิม แต่เห็นกว้างขึ้น ตัวละครใหญ่ขึ้นเล็กน้อย (36% ของสูงเฟรมที่ s=1) · ฉากกว้างพอทุกสเกล
- **overlay** (`L.light`): ชั้นถูกยืด `scale(1.78, 0.5625)` ให้ตำแหน่งออกแบบ 1080×1920 ไปอยู่จุดเดียวกันของเฟรมกว้าง และ **ทุกชิ้นถูกคืนรูป** ด้วย `OVFIX = scale(0.4219,1.3333)` (= ย่อ 0.75 แบบสม่ำเสมอ): ไอคอนทำเองใน `jkicons.js` (`data-ovfix`) ส่วนของที่วาดใน `grp(L.light)` engine ใส่ให้หลัง `fx` (กลุ่มที่ขึ้นต้นด้วย `translate(` หรือ bbox < 900) · สี่เหลี่ยมเต็มจอ (แฟลช/เฟดดำ) ปล่อยให้ยืดเต็มเฟรม
- ของที่ใช้ `L.screen` (แถบดำ เงาข้ามไหล่/หลังหัว มุมมองลอดถัง) วาดด้วย `STAGE_W/H` จึงถูกต้องเอง
- ตัวหนังสือ HTML (`sfxText` `bubbles`) ผ่าน `PX_MAP` (x×1.78, y×0.5625, ฟอนต์ ×0.75) · คำบรรยาย top 880 ฟอนต์ 46 · `.sghud` top 44
- ปรับรายช็อต: `window.LAND_ADJ = { a18: { k:1.1, dx:0, dy:60 } }` ใน head (คูณ s / เลื่อน) ถ้าชีตบอกว่าช็อตไหนเพี้ยน (รอบนี้ไม่ต้องใช้เลย)

## 2. ตรวจหน้าแนวนอนก่อนเรนเดอร์
```bash
(cd $MW/hf/${ST}1L && nohup python3 -m http.server 8782 >/dev/null 2>&1 &)
python3 $S/sheetL.py 8782 ep1L/schedule.json ep1L/sheet1.jpg 20.9 64.2    # 1 เฟรม/ช็อต + เวลาเพิ่ม
```
ดูให้ครบ: ซ้ายบน (แถบสถานะ vs สติกเกอร์นับคน **ห้ามทับ**) · ล่าง (แถวไอคอน vs คำบรรยาย **ห้ามทับ**) · ข้างจอ (ของที่โผล่เพราะเฟรมกว้าง เช่น มังกรสลบในฉากเมือง → ย้ายไป x 1780 s 1.6) · การ์ดกลางจอยังกลาง · POV/แถบดำเต็มเฟรม · ฝุ่น/หมอกไม่หยุดกลางจอ

## 3. เรนเดอร์และประกอบ
```bash
ST=$ST bash renderq.sh 1L 2L      # background task #1 (≤ 2 ตอน/ task)
ST=$ST bash renderq.sh 3L 4L      # task #2 ต่อหลัง #1 จบ — ต่อคิวด้วย sentinel ของตัวเอง (tee log แล้ว grep "QUEUEn-END") ห้าม grep "exit 0"
python3 $S/long169L.py long_plan.json
```
`long_plan.json`:
```json
{ "out": "LONG-<name>-16x9.mp4", "tmp": "longL_tmp", "xfade": 0.2,
  "parts": [ { "video": "ep1L/EP1L-<name>-HQ.mp4", "from": 0.0, "to": 75.055 },
             { "video": "ep2L/EP2L-<name>-HQ.mp4", "from": 2.4, "to": 69.96 },
             { "video": "ep3L/EP3L-<name>-HQ.mp4", "from": 2.6, "to": 63.22 },
             { "video": "ep4L/EP4L-<name>-HQ.mp4", "from": 2.74, "to": 69.58 } ] }
```
- `from` ของตอน 2–4 = จบฮุคของตอน (ดูใน schedule: ช็อตแรกจบ) · `to` = ก่อนการ์ดท้ายตอน · ส่วนที่ตัดถูก cache ตามชื่อไฟล์ต้นทาง+ช่วง → ตอนที่เรนเดอร์ใหม่จะถูกตัดใหม่เอง ตอนอื่นใช้ซ้ำ
- ต่อด้วย concat (เสียงเฟดสั้น 0.2 ที่รอยต่อ ไม่คลิก) แล้วเข้ารหัส crf 18 → ไฟล์ส่งผู้ใช้ (~170 MB) · เข้ารหัสซ้ำ crf 23 → ฉบับ repo (~75 MB)
- เวลาแบ่งตอนที่สคริปต์พิมพ์ → `YOUTUBE.md` (บทที่ 0:00 / 1:15 / 2:22 / 3:23) และ `video/release/<ST>.json`
